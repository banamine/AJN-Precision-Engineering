DESIGN
 Folder: this tool is self-contained under tools/captions-daily/ (Node 22 ESM, no new npm dependency; reuse server/captions/captionCore.ts parseSrt etc. by import or a tiny copied-by-hash shim, ONE implementation) + workflow file captions-daily.yml (to be placed in the private repo's .github/workflows/ and also kept at tools/captions-daily/workflow/ in the app repo for reference).
 Workflow: `on: schedule: cron "23 12 * * *"` (12:23 UTC = after the previous UTC day is complete and TV News Archive items have had time to publish; measure that lag, see P1) + workflow_dispatch (inputs: day, dry_run). `permissions: contents: write` only; `concurrency: group captions-daily, cancel-in-progress: false`; timeout-minutes 60; actions pinned by full commit SHA; NO secrets besides the default GITHUB_TOKEN; never triggers a deploy; fails the run (red) on any cap or request-budget breach, never publishes partial data silently.
 Day definition: previous COMPLETE UTC day (00:00-24:00 UTC) so a rerun is idempotent: same day -> same file bytes (stable ordering: source_kind, channel, start_utc). Idempotent overwrite of that day's file.
 TV items: choose the day's items per approved network from Archive search (ids look like <NETWORK>_YYYYMMDD_HHMMSS_<title>); for each pick the best available caption file by the app's existing preference (aligned > broadcast-cc > asr) and read the WHOLE public SRT once (not 60-s slices; one request per item, ~200 KB). Radio: the 9 items from the app's scheduler for that UTC day (re-derive with the same seed function as server/infowarsRadio.ts; if it cannot be imported offline, document the equivalence test), public .asr.srt whole file.
 CSV schema (UTF-8 with BOM so Excel opens it; RFC 4180 quoting; one row per WINDOW of consecutive cues merged up to 30 s, not per cue, to cut overhead): day_utc, start_utc (ISO, from the item id time + offset; blank only if unknown, never guessed), start_s, end_s, source_kind (tv|radio), channel (network or archive-infowars-radio), program (item title or id), item_id, item_url (https://archive.org/details/<id>), caption_kind (broadcast-cc|aligned|asr), machine_generated (yes|no), genre (from the app's channel/group registry: News, Talk Radio, ...; "unknown" if none), text. No NLP: names/quotes/"meaning" are found by searching the text; do NOT add entity extraction.
 Folder + rotation: data/captions/YYYY-MM-DD.csv plus data/captions/MANIFEST.csv (day, bytes, rows, items_ok, items_skipped, reason counts, sha256). HARD CAP = 50,000,000 bytes for the whole data/captions folder INCLUDING the manifest. Rotation = pure function: after writing a new day, delete the OLDEST whole day files until total <= cap. A single day larger than its budget (cap / RETENTION_DAYS, default RETENTION_DAYS=7 => ~7.1 MB) stops adding items in priority order (config list; radio first or last, owner-set) and records every skipped item in the manifest with reason `day_budget`; if even the manifest + one day exceeds the cap, FAIL loudly. Never truncate text mid-row, never write a partial row.
 Git storage (private repo default): the run builds the folder, commits as ONE new squashed commit (orphan/force-with-lease or `git commit --amend` on a single-commit branch) so history never grows; message contains only counts, never text. A "dry_run" input builds and reports numbers without pushing.
 Search helper (small, optional, offline): tools/captions-daily/search.mjs "<phrase>" [--day YYYY-MM-DD] [--channel X] -> prints matching rows' day, start_utc, channel, program, item_url#t=start_s (no pagination service, no index). Tests use invented text.
